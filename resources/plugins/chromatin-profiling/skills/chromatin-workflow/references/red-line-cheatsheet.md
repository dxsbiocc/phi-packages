# ChIP/CUT&Tag hard red lines × common misreadings quick-reference

For use at runtime. The full decision process (call → read → decide → red lines) is governed by
[`analysis-playbook.md`](analysis-playbook.md); this table compresses each red line into four columns — "red line /
why / common misreading / correct approach" — for a quick self-check at every step.

| # | Hard red line | Why | Common misreading | Correct approach |
| --- | --- | --- | --- | --- |
| 1 | **Pure downstream**: starts from called peaks / counts / BAM / bigWig; no alignment or peak calling | FASTQ→BAM→peak is upstream; ChIP belongs to the nf-core/chipseq wrapper, CUT&Tag to the user's SEACR run | Running bowtie2/MACS2/SEACR inside the plugin, or expecting FASTQ input | The input is BED/narrowPeak/broadPeak, a sample sheet, a count table, indexed BAM; when the upstream part is missing, point to the wrapper or the user's SEACR (CUT&Tag has no wrapper, a gap) |
| 2 | **Read-only environment**: missing packages/references are reported as facts + project environment; no installs, no large reference downloads | The plugin environment is prebuilt and locked; installing packages breaks reproducibility and the signature | Running BiocManager::install / pip-installing idr in the plugin, or downloading a whole-genome GTF into the plugin environment | `chip_env_probe` reports the gap → env_request project environment, or the user supplies GTF/TxDb/org.db/blacklist via input-path |
| 3 | **Lean annotation**: the target-genome TxDb comes from the user; the shipped hg19 TxDb is never a default annotation source | The ChIPseeker conda recipe hard-depends on the hg19 TxDb (build time); it is not the target genome | Annotating hg38/mm10 peaks with the shipped hg19 TxDb; claiming gene symbols were given when there is no org.db | The user's `gtf` (makeTxDbFromGFF) or `txdb` (loadDb); without one report the gap; without org.db report gene ids, not symbols |
| 4 | **The blacklist is genome-build specific**: hg38 regions are wrong on mm10 | Passing the wrong build silently deletes the wrong loci and contaminates the consensus and the differential analysis | Defaulting to hg38 and applying it to mouse without passing genome; or skipping the blacklist altogether | Pass `genome` (hg38/mm10) for the inlined ENCODE v2, or `blacklist` for another build; with neither, skip and say so |
| 5 | **DiffBind vs csaw is a biology decision** | TF/narrow mark signals are sharp peaks and suit peak-based analysis; broad mark signal is diffuse over kilobases and peak-based analysis misses it | Running H3K27me3 all the way through DiffBind; or stubbornly waiting for csaw on Apple Silicon | TF/narrow (H3K4me3/H3K27ac) and CUT&Tag→DiffBind (DESeq2/edgeR); broad (H3K27me3/H3K36me3/H3K9me3)→csaw; csaw is a gap on darwin-arm64, substitute DiffBind or move to linux-x64/darwin-x64 |
| 6 | **FRiP is the headline signal-to-noise metric and thresholds come from the distribution; IDR is a gap** | Low FRiP = the antibody did not enrich, most reads are background; IDR needs the idr pip package, which the environment does not carry | Taking FRiP thresholds from defaults; presenting the peak overlap fraction as a formal IDR conclusion | Read the frip distribution from `chip_qc` before judging (TF ChIP ideally >1%, broad lower, CUT&Tag often very high); the overlap fraction is a transparent proxy — say clearly that it is not IDR |
| 7 | **The replicate is the experimental unit, not the peak** | The replicates behind a condition-level claim are biological samples; peaks are an observation dimension, not replicates | Treating thousands of peaks as replicates for a condition contrast; claiming a condition difference with 1 sample per group | Make condition-level claims only with ≥ `min_members` (default 2) biological replicates per group; otherwise describe within-sample patterns only |
| 8 | **Normalized/exploratory counts never feed the differential test** | DESeq2/edgeR/csaw each normalize internally (median-of-ratios/TMM); external CPM breaks the mean-variance assumption | Feeding `chip_count`'s normalized_counts into the differential test | normalized_counts are only for PCA/visualization; differential analysis goes back to raw counts and the engine normalizes internally |
| 9 | **consensus / min_occupancy is a region-universe decision** | How many samples a locus must appear in to enter the consensus fixes the full interval set tested and the multiple-testing burden | Taking min_occupancy from a default and running it throughout; building the consensus without blacklist filtering | Blacklist-filter first, then consensus; set min_occupancy by replicate number and biological question; state the choice and the reason |
| 10 | **Annotation/motif is inference/prediction, not measured regulation** | ChIPseeker annotates to the nearest gene by position; motif enrichment is an over-representation test at the sequence level | Treating peak annotation as measured target-gene regulation; treating motif hits as measured TF binding | Annotation is a positional inference and needs expression/functional validation; motif enrichment (HOMER/MEME) is a gap, not in the R downstream stack — when it is needed, report the gap and go via a project environment |
| 11 | **DiffBind needs a sample sheet + indexed BAM** | dba(sampleSheet=) builds the DBA from the sheet; counting/FRiP needs .bai indexes | Forcing a diff run without a sheet; counting on BAMs with no index | diff/count/qc start from a DiffBind sample sheet (the Peaks/bamReads columns drive loading, relative paths resolve against the sheet directory); BAMs need .bai (samtools index is upstream) |
| 12 | **The JSON is the audit record; "not run" is not "no problem"** | The before/after counts and gaps returned by each step are the delivery evidence | Recomputing numbers the tools already gave; describing the csaw gap/annotation gap as completed | Quote the peak counts/FRiP/occupancy/differential counts/feature distribution from the tool JSON; state explicitly which step did not run for lack of a package or reference |

## How to use

- Before each step, scan the rows relevant to it (QC→1/6/11; consensus→4/9; count→8/11; diff→5/7/8/11; annotate→3/10; any heavy dependency→2/5).
- Before delivery, check row 2 (were missing packages/references installed into the plugin or described as no problem) and row 12 (was "not run" described as "no problem").
- Thresholds and strategies are always "read the distribution/report first, then decide", never a priori defaults. Quote the numbers in the tool JSON; do not recompute them yourself.
